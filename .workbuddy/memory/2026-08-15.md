## 🔴 演示模式失败的真正根因 + 系统性修复（08:20-09:00）

### 根因 1（主因）：Tauri v2 IPC 参数名默认 camelCase，前端 api 层全用 snake_case
- Tauri v2 `#[tauri::command]` 默认把 Rust 参数名转 **camelCase** 供 JS 端匹配（`task_id` → `taskId`），返回值保持 snake_case。
- 前端 api 层（taskApi/notesApi/financeApi/calendarApi/authApi/syncApi）invoke 传参几乎全用 snake_case：
  - **必填多词参数** → 报 `missing required key taskId` 之类（subtask_create 首当其冲，seed 在第一个子任务崩溃）；
  - **可选多词参数** → **静默丢失**（tag_ids/due_date/is_pinned/folder_id/amount_cents 等全失效，此前 task_tags 一直是 0 条！）。
- 错误对象是 **String 而非 Error** → authStore.enterDemo 兜底文案「进入演示模式失败」（e 不是 Error 实例）。
- **修复**：6 个 api 文件全部 invoke 参数改 camelCase（含 null_fields → nullFields、sync_config_save 内嵌 config 字段）。
- ⚠️ 教训：mailApi / tauri.ts(set_close_behavior closeOnExit) / receipt_save(dataBase64) 本来就是 camelCase（所以这些功能正常）；写新 Tauri 命令务必参数名用 camelCase，或前端按 Tauri 约定传参。

### 根因 2：note_folders 表缺 updated_at 列
- 建表定义漏了 updated_at，但 note_folder_create/update SQL 引用 → `no column named updated_at`。
- **修复**：db.rs SCHEMA_VERSION 6→7，新增 migrate_v7（pragma_table_info 检查后 ALTER + 历史行回填 created_at；全新库 create_all_tables 同步加列）。

### 根因 3：data_clear_all / data_import_all 删除顺序触发外键
- 原按 BACKUP_TABLES（父表优先）逐表 DELETE → 删 accounts 时 transactions 仍引用 → `FOREIGN KEY constraint failed`（完整 seed 后清场必现）。
- **修复**：新增 CLEAR_ORDER（子表优先）+ 删除前断开自引用（categories/note_folders parent_id 置 NULL），data_import_all 清场同样处理。
