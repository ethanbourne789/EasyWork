## 绿色版启动白屏修复：缺 `custom-protocol` + CSP 太严（13:49）
用户启动 `release-green/EasyWork.exe` 后白屏，报错「嗯… 无法访问此页面 / localhost 拒绝连接 / ERR_CONNECTION_REFUSED」。根因与修复：

1. **Tauri v2 release 构建缺 `custom-protocol` feature**：`tauri` crate 的 `build.rs` 以 `dev = !custom_protocol` 判定模式。`cargo build --release` 若不带 `--features custom-protocol`，Tauri 会认为仍是 dev 模式，**不嵌入 `frontendDist` 资源**，启动时直接去连 `devUrl`（`http://localhost:1420`），无 dev 服务器便报错。
   - 修复：`src-tauri/Cargo.toml` 新增 `[features] custom-protocol = ["tauri/custom-protocol"]`；`scripts/build-green.ps1` 的 cargo 命令改为 `cargo build --release --features custom-protocol`。
   - 结果：exe 体积从 8.33 MB 涨到 9.02 MB（前端 dist 已嵌入）；二进制中同时出现 `tauri.localhost`；`localhost:1420` 只是 `devUrl` 配置字符串（被 `#[cfg(dev)]` 门控，运行期不会使用）。

2. **CSP 阻止 Supabase 连接**：原 CSP 没有 `connect-src`，继承 `default-src 'self'`，前端无法向 `https://nbcsywzqvvputqitmpla.supabase.co` 发请求。
   - 修复：`tauri.conf.json` 的 CSP 增加 `connect-src 'self' https:`。

重新 `npm run build:green` 产出 `release-green/EasyWork.exe`（9.02 MB，13:49），前台 cargo 构建通过，dumpbin 确认仍无 `VCRUNTIME140`/`MSVCP140`。
